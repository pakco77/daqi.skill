# Interactive Mono Dither Camp Design

**Status:** Approved visual and interaction direction (fourth prototype, 2026-08-14). This document defines the production design; it does not authorize writes to Daqi stores.

## Product narrative

The camp is not a dashboard with a landscape banner. It is a read-only spatial index for Daqi's real local state. A user opens one stable scene, sees three functions attached to physical objects, moves closer to an object, and reads a small archive panel without losing the camp around it.

The primary user action is **choose a place in the camp**. The visible result is a focused view backed by the exact local file responsible for that place.

## Scope

### In scope

- Replace the current vertical report layout generated by `camp_status.py` with one desktop-first, single-viewport camp.
- Keep the output as one self-contained HTML file with no network request and no runtime dependency.
- Render three scene-bound functions:
  - **营地账本 / 情报 · 点子 · 计划** at the archive desk beside the tent.
  - **马厩 / 干一票** at the stable and hitching area.
  - **火 / 你是谁？** at the campfire.
- Support pointer click, keyboard navigation, and a downward-wheel back gesture.
- Select day or night from the browser's local time, with a persistent manual override.
- Render the camp and panels in the approved Mono Dither UI / Grayscale Dither Archive language.
- Read project `NOW.md` files to show “这票到哪了” inside the stable flow.

### Out of scope

- Creating, editing, promoting, or deleting intel, ideas, plans, projects, profile entries, or NOW state.
- Writing to `POOL.md`, `SHELF.md`, `SELF.md`, any project `NOW.md`, or another store file.
- A local server, login, geolocation, cloud sunrise service, analytics, or external asset request.
- Mobile parity. Narrow windows receive a readable fallback, not a second mobile product.
- Inferring profile traits that are absent from `SELF.md`.

## Read-only data contract

The renderer may read only these sources:

| Scene function | Source | Fields shown |
|---|---|---|
| 营地账本 | `<STORE_ROOT>/POOL.md` | stage, entry text, `last_seen` |
| 马厩 | `<STORE_ROOT>/SHELF.md` | project name, exact project path, last active time, Agent |
| 这票到哪了 | `<project path>/00_Context/NOW.md` | Goal, Verified now, Next, Done when |
| 火 | `<STORE_ROOT>/SELF.md` | confirmed profile entries and confirmed long-term goals |

Rules:

- `POOL.md` has no Agent field. The ledger must never display or infer an Agent.
- Agent and last active time appear only on stable project rows and come directly from `SHELF.md`.
- A project row may read only the exact `00_Context/NOW.md` below the project path recorded in `SHELF.md`. Do not search sibling directories or substitute another root.
- A missing or unreadable project `NOW.md` does not break the camp. The project detail panel says that no current checkpoint is available.
- A missing `SELF.md`, an initialized template, placeholder values such as `<...>`, or an empty profile produces the honest state: “现在还认不出你”. Placeholder and policy text must never render as user traits.
- Profile rendering follows the file's actual sections and preserves confirmed wording. Useful groups are industry, occupation, age band, life routines, decision style, quality bar, communication preferences, authorization boundaries, and long-term goals. Omit empty groups.
- Existing behavior remains fail-closed when `POOL.md` or `SHELF.md` is missing: report the incomplete exact store and do not generate a substitute camp from another root.
- The only write is the derived HTML path selected by `--out` or the existing `<STORE_ROOT>/camp.html` default.

## Information architecture

### 1. Camp overview

The overview keeps all three functions visible at once. Each name sits next to its physical object, with the approved subtitle directly below it:

- 营地账本 — 情报 · 点子 · 计划
- 马厩 — 干一票
- 火 — 你是谁？

These are product labels, not floating debug hotspots. Tents, trees, mountains, lake, and stars remain atmosphere unless they receive a real function later; decorative objects must not look clickable.

### 2. Ledger focus

Selecting the archive desk moves the scene closer and raises a compact paper panel in open scene space. The panel does not touch a viewport edge and does not fill the screen height.

The primary controls are three Tags:

- 情报
- 点子
- 计划

Each Tag includes its count and filters the same panel in place. Rows show only the entry text and last-seen time. Show at most five rows per page; use compact previous/next pagination instead of vertical list scrolling.

### 3. Stable focus

Selecting the stable moves the scene closer and raises the same-sized paper panel on the opposite side, preserving the stable in view.

The primary Tags are computed from each parseable last-active date at render time:

- **在跑:** fewer than 7 full days since last activity.
- **7 天没动:** 7–29 full days since last activity.
- **30 天没动:** 30 or more full days since last activity.

If an entry has a missing or unparseable date, add a conditional **时间未知** Tag rather than placing it in a false time band.

Each project row shows project name, Agent, and human-readable last active time. Selecting a project replaces the list inside the same light panel with **这票到哪了**; it must not open a larger modal or another page.

The project detail uses four fields from `NOW.md`:

- 目标
- 已验证
- 下一步
- 完成条件

Returning from this nested detail restores the stable list and its selected time Tag.

### 4. Fire focus

Selecting the fire moves the scene closer and raises a compact panel titled **达奇对你的认知**. It renders only confirmed material from `SELF.md`.

When no valid profile entry exists, show:

- Title: **现在还认不出你**
- Explanation: the profile has not been established and Daqi will not treat placeholders, chat impressions, or unconfirmed inferences as the user's file.

The fire view does not offer an edit control in this read-only version.

## Interaction model

- **Click:** selecting a named scene function focuses its object and opens its panel.
- **Scene focus:** use a small pan and scale change so the object moves nearer to a clear third of the viewport. Do not replace the background or simulate a page change.
- **Panel entry:** outline appears first, content develops in 6–8 discrete frames. No full-height drawer.
- **Downward wheel（鼠标向下滚动）:** move back exactly one visual level.
  - NOW detail → stable project list.
  - Ledger, stable list, or profile panel → camp overview.
- Treat one continuous wheel movement as one gesture. Accumulate a small positive threshold, navigate once, then lock until the wheel settles so one physical gesture cannot skip two levels.
- Downward wheel at the overview does nothing and must not move the document.
- **Escape:** same one-level-back behavior as downward wheel.
- **Explicit back control:** always available while focused and uses the same one-level-back behavior.
- **Tags:** click switches content in place and preserves scene focus.
- **Pagination:** buttons change list pages without stealing the downward-wheel back gesture.
- **Keyboard:** Tab reaches time controls, scene functions, Tags, project rows, pagination, and back controls in visible order. Enter/Space activates; Escape goes back. Focus is visibly outlined.
- Do not map ordinary vertical wheel movement to horizontal scene selection.

## Day and night

- `AUTO` reads the browser's local clock, which follows the user's current system time zone without requesting location.
- Local time from `06:00` inclusive to `18:00` exclusive renders day; all other times render night.
- The user can choose `白天` or `黑夜` manually. Store only this display preference in browser `localStorage`; never put it in a Daqi store.
- Selecting `自动` removes the manual override and resumes local-time behavior.
- Day and night use the same composition and exact hotspot coordinates. The scene must not move functions between modes.
- Day has a weaker flame and more legible smoke. Night has a brighter micro-yellow flame. The fire is the only chromatic element.
- Automatic mode should re-evaluate while the page remains open so a boundary crossing does not require regeneration.

## Mono Dither UI visual contract

### Palette

- Warm paper: `#F2F2EE`
- Secondary paper: `#E5E5E0`
- Panel: `#FAFAF7`
- Primary text: `#111111`
- Secondary text: `#72726C`
- Border: `#C9C9C2`
- Scene black: `#050505`
- Reverse text: `#F5F5F2`
- Flame: restrained micro-yellow around `#DFB35A`, with a small pale core around `#FFF0B6`

The original 65% cream ratio applies inside information panels and reading surfaces, not to the whole viewport. The scene remains the dominant surface.

### Scene imagery

- Use one stable camp composition with archive desk, central fire, stable, tents, mountains, lake, and trees.
- Night imagery uses high-contrast 1-bit Floyd–Steinberg character. Day may use four gray levels where needed to preserve object separation.
- Day and night assets must share geometry; day is not a simple color inversion of night.
- Preserve visible pixel grain with `image-rendering: pixelated` where raster assets are used.
- Hard CSS patterns are allowed for dither and checker texture. Soft tonal gradients, blur, ordinary shadows, CRT scanlines, glitch, and RGB split are not.

### Panels and controls

- One-pixel borders, 0–2px radius, no ordinary drop shadow.
- Modern system sans-serif for names and body copy.
- Monospace only for counts, Agent labels, dates, time, and compact status.
- Default control: paper background, dark text, gray border.
- Hover: black/white inversion.
- Selected Tag: dense monochrome Bayer/checker fill plus reverse text; selection must not rely on color.
- Keep labels and readable text at practical desktop sizes. Pixel character comes from imagery and state texture, not from sacrificing legibility.
- Remove decorative terminal copy. Visible metadata must answer a user question.

### Motion

- Fire uses a short 6–8-frame stepped loop, not a smooth morph. The flame remains micro-yellow and restrained.
- Focus pan/scale, panel reveal, and day/night development use `steps()` or a small discrete frame sequence.
- Motion explains cause, depth, and state. No ambient floating UI.
- Under `prefers-reduced-motion: reduce`, remove camera interpolation, panel development, smoke travel, and flame looping; keep clear instantaneous state changes.

## Layout and responsive behavior

- Primary validation sizes: 1280×800, 1440×900, and 1728×1117-class desktop viewports.
- The camp fills the available viewport without document-level vertical scrolling during normal use.
- Focus panels occupy roughly 36–42% of scene width and remain detached from viewport edges.
- At narrower desktop widths, reduce camera movement and allow the panel to reach roughly 48% width while keeping the selected object visible.
- Below the supported desktop minimum, fall back to a readable stacked archive view. Do not preserve a broken miniature scene or claim mobile parity.

## Error and empty states

- Empty ledger Tag: say that no item is in that stage; keep the other Tags available.
- Empty stable time Tag: say that no project is in that time band.
- Invalid stable date: place the project under a conditional `时间未知` Tag and display the source value without guessing.
- Missing project path or NOW file: keep Agent/time metadata visible and say that no current checkpoint is available.
- Empty SELF profile: use the approved “现在还认不出你” state.
- Parse warnings remain available in generated HTML for diagnosis but must not occupy the main scene. Use a compact, meaningful notice only when a warning affects visible data.
- Missing required `POOL.md` or `SHELF.md`: preserve the existing command-line error and do not write output.

## Implementation boundaries

- Extend the existing `camp_status.py`; do not introduce a frontend framework, package manager, build step, runtime server, or new dependency.
- Reuse the existing parsers and image helpers where they still match the new contract. Add the minimum parsing needed for SELF and project NOW files.
- Namespace scene objects, panels, and state classes so a name such as `stable` cannot style both a physical stable and its information panel.
- Keep all CSS and JavaScript embedded in the generated HTML.
- Keep script behavior deterministic from parsed data plus browser-local time/preference.
- Preserve source-file bytes before and after rendering in tests.

## Verification contract

Production work is complete only after these checks pass:

1. Existing Chinese and English parsing, empty-store, missing-store, warning, and read-only tests still pass.
2. New parser tests cover valid profile entries, placeholder-only SELF, all four NOW sections, missing NOW, valid activity dates, and invalid activity dates.
3. Generated HTML contains the three approved scene labels, Tag controls, Agent/time only in stable rows, and no removed engineering labels.
4. Store files and project NOW files have identical bytes before and after rendering.
5. Browser interaction checks cover:
   - local-time day/night selection;
   - persistent manual override and return to automatic mode;
   - all three scene functions;
   - every Tag switch;
   - stable row → NOW detail → one-level back;
   - downward wheel and Escape one-level back;
   - keyboard focus order;
   - reduced-motion behavior.
6. Screenshots at the target desktop sizes are visually inspected in both day and night states.
7. Browser validation remains local proof only. It does not prove behavior in every Agent host or change any external/live state.
